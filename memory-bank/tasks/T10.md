## Description
The token-usage skill does not treat all session formats the same. The direct parser now reads Codex rollouts, but the SQLite importer and some reports do not. The docs also list commands that the parser does not accept.

## Acceptance Criteria
- [ ] One shared parser handles OpenClaw messages and Codex rollouts.
- [ ] OpenAI, Claude, Kimi, and other known providers use the right model name and price.
- [ ] Unknown models never use Kimi prices by mistake.
- [ ] Cached tokens are counted and priced where supported.
- [ ] Direct reports and SQLite reports agree on the same input files.
- [ ] Documented command flags match the actual CLI.
- [ ] Tests cover providers, gzip files, aliases, caches, and timezone boundaries.

## Implementation Details
First move common parsing and model normalization into one small module. Then use it from `parse.py` and `ingest.py`. Keep new usage as input plus output, and show cached input separately.
