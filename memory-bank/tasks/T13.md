### First-hand observations recorded
Instance B (Cloudy) was the live subject experiencing tool degradation in
real-time on a kimi/k3 Telegram session. The following were observed
first-hand and added to the shared report:

1. **Timeline of degradation**: Context 144k → 95k (first oscillation, 0
   compactions) → tools die at ~134k → context climbs to 149k → 155k → 153k
   (second oscillation, 0 compactions).
2. **Silent tool death description**: What it looks like from the inside —
   tool calls return empty structures, no errors, chat continues normally.
3. **Delivery-copy duplication discovery**: Assistant messages appearing 2–3x
   in Telegram context. Later corrected to include user message duplication.
4. **Persistent failure confirmation**: Tools remained dead across 10+ turns
   and multiple tool types once they failed.
5. **Theory correction**: Instance B incorrectly used "bricked" (session was
   healthy) and initially claimed only assistant messages were duplicated.
   Both corrected in the signed-off report.
