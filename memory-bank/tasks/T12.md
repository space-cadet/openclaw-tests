## Description
Create a lightweight background monitor that detects whether OpenClaw's harness is causing retry storms when "All models are temporarily rate-limited" errors occur. The monitor tails the OpenClaw gateway log (not network connections, since `lsof` hostname filtering fails on macOS) and tracks in-flight Kimi requests, burst patterns, and HTTP 429 responses.

## Scope
1. **Background Monitor Script** — `scripts/kimi-retry-monitor.sh` with `start|stop|status|run|check` commands
2. **macOS LaunchAgent** — `launchd/ai.openclaw.kimi-retry-monitor.plist` for auto-start at login
3. **Burst Detection** — Alerts when ≥3 requests in-flight simultaneously or ≥4 starts within 10 seconds
4. **429 Detection** — Logs explicit ALERT entries for rate-limit responses
5. **Log Query Tool** — `check [minutes]` command produces verdict: retry storm vs API-side throttling vs no issue

## Design Decisions
- **Gateway log over `lsof`**: macOS `lsof` resolves hostnames to IPs before displaying, so `grep agent-gw.kimi.com` returns nothing. The gateway log at `~/Library/Logs/openclaw/gateway.log` already contains structured request/response lines with model names and status codes.
- **Tail -F over polling**: `tail -n 0 -F` follows log rotation and only processes new lines, making it efficient.
- **In-flight counting**: Increment on `[provider-transport-fetch] ... start provider=kimi`, decrement on `... response provider=kimi`. This gives real-time concurrency without packet capture.
- **Burst thresholds**: 3 in-flight (concurrency) or 4 starts in 10 seconds (rapid-fire). These are conservative; adjust based on observed patterns.
- **macOS daemonization**: `setsid` is not available on macOS. The script uses subshell + `disown` for backgrounding. The LaunchAgent is the preferred long-term mechanism.

## Usage
```bash
# Start/stop/status
./scripts/kimi-retry-monitor.sh start
./scripts/kimi-retry-monitor.sh status
./scripts/kimi-retry-monitor.sh stop

# Query after a rate-limit error
./scripts/kimi-retry-monitor.sh check 10   # last 10 minutes
```

## Notes
- Gateway log path is hardcoded to `~/Library/Logs/openclaw/gateway.log` (macOS default). For Linux, this would be `/var/log/openclaw/` or similar.
- Monitor log directory: `~/.openclaw/logs/kimi-monitor/` (created automatically)
- The script is Kimi-specific (`provider=kimi`) but could be extended to other providers by changing the grep pattern.
