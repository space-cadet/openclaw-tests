## Description
Design a provider- and model-agnostic availability study for measuring request success, failure classes, latency, and outage patterns over time. The measurement path must work both when the OpenClaw harness is available and when it is unavailable. Every attempt must be recorded in JSONL, and measurement jobs must never depend on agentic tools.

## Acceptance Criteria
- [x] Define a provider/model-agnostic probe contract and JSONL event schema.
- [x] Define direct and OpenClaw-mediated harness modes without mixing their results.
- [x] Define silent measurement scheduling and notification-producing aggregate schedules.
- [x] Integrate maintenance-mode and naming requirements from `cron-management`.
- [x] Specify hourly and four-hourly statistics windows and duplicate/retry handling.

## Implementation Details
The direct harness is the primary availability measurement path: an OS scheduler invokes a standalone provider adapter. An optional OpenClaw harness may measure the agent-mediated path, but it is a distinct condition and must be labelled as such. Both write append-only JSONL events to the same schema. Measurement jobs use no Telegram delivery. Separate reporting jobs may send statistics for the preceding one-hour and four-hour windows.

All jobs should check the cron-management maintenance flag before making network calls. OpenClaw jobs should use explicit silent/no-reply delivery for measurements and descriptive names compatible with `cronctl` fuzzy matching.
